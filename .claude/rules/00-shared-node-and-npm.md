## Node & npm Version — Install With What CI Uses

**All three apps are pinned to Node 20 / npm 10.** This is not a preference:
`backend/Dockerfile` builds and runs on `node:20-alpine`, and every CI workflow
uses `node-version: '20'`. The lock files must be generated by the same npm
major that CI runs, or `npm ci` fails on a lock that works perfectly locally.

Each app has a `.nvmrc` and an `engines` field. Before installing anything:

```bash
nvm use          # picks up .nvmrc → Node 20
npm install <pkg>
```

**If you are on a newer Node**, do not run a bare `npm install` — generate the
lock with CI's npm instead:

```bash
npx -y npm@10 install --package-lock-only
```

**How this fails, concretely.** `swagger-jsdoc` pins `yaml@2.0.0-1`, while
`vite` (via `vitest`) declares `yaml@^2.4.2` as an *optional peer*. npm 10
materialises that optional peer as a nested
`node_modules/vitest/node_modules/yaml@2.9.0`; **npm 11 prunes it**. Running
`npm install` under npm 11 silently dropped that entry, and CI then failed
with:

```
npm error `npm ci` can only install packages when your package.json and
npm error package-lock.json ... are in sync.
npm error Missing: yaml@2.9.0 from lock file
```

The lock was not corrupt and the local install was fine — the two npm majors
simply disagree about optional peers.

**Reproduce a CI install failure locally** without pushing:

```bash
npx -y npm@10 ci --dry-run
```
