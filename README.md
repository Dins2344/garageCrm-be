# GaragePulse API

Backend for GaragePulse, a multi-tenant garage/workshop CRM. Handles job cards,
estimations, invoicing, inventory, customers, vehicles, staff and service
reminders, with every record scoped to a garage.

**Stack:** Node 20 · Express 5 · Mongoose 9 · TypeScript · Vitest · Winston · JWT

Companion repositories: [`garageCrm-fe`](https://github.com/Dins2344/garageCrm-fe)
(web) and [`garageCrm-app`](https://github.com/Dins2344/garageCrm-app) (mobile).
All three deploy independently.

---

## Prerequisites

- **Node 20** and **npm 10** — pinned in `.nvmrc` and `engines`. A lock file
  generated by a newer npm will fail CI's `npm ci`, so run `nvm use` first.
- **MongoDB** — a local instance or a MongoDB Atlas connection string. The test
  suite does not need one; it spins up its own in-memory server.

## Getting started

```bash
nvm use                                  # Node 20
npm ci                                   # exact dependency install
cp .env.production.example .env          # then fill in the values below
npm run dev                              # tsx watch, http://localhost:5000
```

Check it is alive:

```bash
curl http://localhost:5000/api/health
```

Interactive API docs are served at **http://localhost:5000/api-docs**
(OpenAPI JSON at `/api-docs.json`).

## Environment variables

Copy `.env.production.example` and fill it in. `.env*` files are gitignored —
only the `.example` is tracked.

| Variable | Required | Notes |
| --- | --- | --- |
| `PORT` | no | Defaults to `5000` |
| `NODE_ENV` | yes | `development` / `production` / `test` |
| `MONGODB_URI` | yes | Connection string |
| `JWT_SECRET` | yes | Use a long random value |
| `JWT_EXPIRE` | yes | e.g. `30d` |
| `CLIENT_URL` | yes | Web app origin, used for CORS and password-reset links |
| `SMTP_HOST` `SMTP_PORT` `SMTP_SECURE` `SMTP_USER` `SMTP_PASS` `SMTP_FROM` | no | Email. Unset means email is logged, not sent |
| `TWILIO_ACCOUNT_SID` `TWILIO_AUTH_TOKEN` `TWILIO_PHONE_NUMBER` | no | SMS. Unset means SMS is logged, not sent |
| `SUPER_ADMIN_EMAIL` `SUPER_ADMIN_PASSWORD` `SUPER_ADMIN_SECRET` | **yes in production** | See the warning below |

> **Set the `SUPER_ADMIN_*` variables in any deployed environment.**
> `usecases/adminUsecase.ts` falls back to a hardcoded email and password when
> they are missing, so an environment that does not set them exposes the
> platform-admin console on publicly known credentials. They are deliberately
> absent from `.env.production.example`; add them to your deployment's secrets.

## Testing

Vitest + Supertest against a real, ephemeral MongoDB (`mongodb-memory-server`),
so tests exercise actual garage-scoping queries, schema validators and indexes
rather than mocks of Mongoose. Email and SMS services are mocked globally in
`tests/setup.ts` — no test ever contacts a real provider.

```bash
npm test
```

Tenant-isolation tests are mandatory for any new garage-scoped entity: prove
Garage B gets a 404, not the data, for a resource owned by Garage A. See
`tests/tenantIsolation.test.ts`.

## Architecture in one line

`route → controller → usecase → model`. Controllers are thin HTTP adapters,
usecases hold all business logic and never touch `req`/`res`, models define
schema and indexes only.

`app.ts` builds the Express app with no import side effects so tests can
`supertest` it. `server.ts` is the only file that connects the database and
starts cron, SMS and mail.

## Deployment

Pushing to `main` triggers `.github/workflows/deploy.yml`, which builds a
multi-stage Docker image (`node:20-alpine`), pushes it to Docker Hub, and
redeploys on EC2 via `docker compose`, finishing with a health check. The
workflow can also be run manually (`workflow_dispatch`).

Before pushing a dependency change, confirm the lock file still satisfies CI's
npm:

```bash
npx -y npm@10 ci --dry-run
```
